AZ-104 · Dominio 3 · Cómputo

Cómputo: conectar, escalar, desplegar con código y contenedores

En AZ-900 viste qué son las VMs, los Scale Sets, App Service y los contenedores. AZ-104 pregunta cómo se administran: entrar a una VM sin exponerla con Bastion, las reglas de autoescalado, desplegar con ARM y Bicep y elegir entre ACI, Container Apps y AKS (PDF AZ-104, págs. 113–155).

Repaso de la base AZ-900

Portal, CLI, PowerShell, Cloud Shell y plantillas ARM: cap. 4 · VMs, opciones de compra, escalado vertical y horizontal con zonas, App Service, ACI y AKS: cap. 5.

1 · ¿Cómo me conecto a la VM?

Abrir RDP (3389) o SSH (22) a Internet es el error clásico. Azure Bastion es un PaaS que te da RDP y SSH desde el portal, por una conexión cifrada, sin IP pública en la VM (págs. 128–130).

2 · Scale Set: reglas de autoescalado

Un Scale Set crea y quita VMs idénticas según reglas sobre una métrica (CPU, memoria, tráfico), en modo automático, manual o combinado (pág. 125). Supuesto: cada VM atiende 100 unidades de carga al 100% de CPU; la regla mira la CPU media de cada intervalo y actúa en el siguiente.

3 · Infraestructura como código: ARM vs Bicep

Una plantilla ARM describe los recursos en JSON declarativo; Bicep describe lo mismo con una sintaxis más corta y se transpila a JSON ARM con bicep build. Las dos se despliegan con Azure Resource Manager (págs. 131–135). Cambia los parámetros y mira las dos versiones.

5 · Lo que más pregunta AZ-104 de este dominio

    

      
Escalar (págs. 118–123)
    
        
  • Vertical (scale up/down): VM más grande, desde 0,5 GB y 1 vCPU hasta 11,4 TB y 416 vCPU. Tiene límites y puede ser caro.
    • 
        
  • Horizontal (scale out/in): más instancias, con Scale Sets y Load Balancer.
    • 
        
  • Alta disponibilidad: la app en al menos 2 zonas.
    • 
        
  • Elasticidad = autoescalado según la carga. Agilidad = recursos en minutos, no semanas.
    • 
      

      
Scale Sets (págs. 124–127)
    
        
  • Orquestación Uniform: VMs idénticas desde una imagen o plantilla.
    • 
        
  • Orquestación Flexible: puedes mezclar tamaños y configuraciones.
    • 
        
  • Se integran con Load Balancer (capa 4) o Application Gateway (capa 7).
    • 
        
  • Sin costo adicional: pagas las VMs, discos y red.
    • 
      

      
Azure Bastion (págs. 128–130)
    
        
  • PaaS: RDP y SSH desde el portal, por TLS (443).
    • 
        
  • La VM solo necesita IP privada.
    • 
        
  • Subred propia llamada exactamente AzureBastionSubnet, en la misma VNet o en una emparejada.
    • 
        
  • Roles de lectura sobre la VM, su NIC y el recurso Bastion.
    • 
      

      
Datos de usuario de la VM (págs. 116–117)
    
        
  • Script que corre al crear la VM, ej.: apt-get -y install nginx para que arranque como servidor web.
    • 
        
  • Así la VM queda configurada sin entrar a mano.
    • 
      

      
App Service (págs. 136–141)
    
        
  • PaaS: Microsoft gestiona el SO, la capacidad, el balanceo y el autoescalado.
    • 
        
  • Web Apps (sitios), Web App para contenedores (Docker), API Apps (servicios web).
    • 
        
  • El servicio es gratis; pagas los recursos que consume (el plan).
    • 
      

      
Docker (págs. 143–147)
    
        
  • Dockerfile: instrucciones para crear la imagen.
    • 
        
  • Imagen: archivo por capas con todas las dependencias.
    • 
        
  • Contenedor: una instancia de la imagen, aislada.
    • 
        
  • Más ligero que una VM: comparte el SO del servidor.
    • 
      

      
Azure Container Registry (pág. 149)
    
        
  • Registro privado de imágenes, integrado con ACI, AKS y Container Apps.
    • 
        
  • Acceso con Entra ID y RBAC, escaneo de vulnerabilidades, etiquetas, limpieza automática y CI/CD (GitHub Actions, Azure DevOps).
    • 
      

      
Bash para administradores (págs. 20–22)
    
        
  • ls -la listar · cd cambiar carpeta · mkdir / rmdir · rm -r · cp -i · touch · cat · sudo.
    • 
        
  • ps -ef procesos · w usuarios conectados.
    • 
        
  • > sobrescribe · >> agrega · < lee de un archivo · | pasa la salida a otro comando.
