Monitoreo y copias de seguridad: alertar, consultar, recuperar

En AZ-900 viste qué hace cada herramienta de Azure Monitor. AZ-104 pregunta cómo se configura: las partes de una regla de alerta, consultas KQL en Log Analytics y cómo recuperar datos con Azure Backup y Site Recovery (PDF AZ-104, págs. 190–202).

Repaso de la base AZ-900

Azure Monitor, Log Analytics, Application Insights, alertas y grupos de acción, Service Health, Advisor y Arc: cap. 10 · Redundancia del almacenamiento y región emparejada: cap. 7.

1 · Arma una regla de alerta

Una regla de alerta tiene recurso + señal (la telemetría) + condición (umbral durante una ventana de tiempo) + gravedad + grupo de acción (qué hacer). Ejemplo del curso: VM, uso de disco > 80% durante 10 minutos, gravedad crítica (pág. 200). La línea muestra 30 minutos de la señal, minuto a minuto.

min 1min 15min 30
bajo el umbralsobre el umbralla alerta se dispara

4 · Lo que más pregunta AZ-104 de este dominio

    

      
Qué envía una VM a Monitor (pág. 192)
    
        
  • Métricas de rendimiento (números en el tiempo: CPU, disco, red).
    • 
        
  • Registros: actividad, diagnóstico, red, seguridad y auditoría, aplicaciones.
    • 
        
  • Para registros del SO invitado hace falta el agente (extensión de monitoreo).
    • 
      

      
Log Analytics y KQL (págs. 196–197)
    
        
  • Almacena y consulta los registros en un área de trabajo.
    • 
        
  • KQL: Tabla | where … | summarize … by … | order by ….
    • 
        
  • Tablas típicas: Perf, Heartbeat, AzureActivity, Event.
    • 
      

      
Application Insights (pág. 198)
    
        
  • Para aplicaciones web: cuellos de botella, tiempos de respuesta, interacción de los usuarios.
    • 
        
  • Funciona con App Service, VMs (necesitan agente) y recursos fuera de Azure.
    • 
      

      
Alertas y grupos de acción (págs. 199–200)
    
        
  • Regla = recurso + señal + condición + gravedad + grupo de acción.
    • 
        
  • Grupo de acción: email/SMS, Logic Apps, Azure Functions, webhook, etc. Se reutiliza en muchas reglas.
    • 
        
  • Gravedad de 0 (crítica) a 4 (detallada).
    • 
      

      
Almacén de Recovery Services (no está en el PDF)
    
        
  • Guarda los puntos de restauración de VMs, Azure Files, SQL en VM, etc.
    • 
        
  • Para respaldar una VM, el almacén debe estar en la misma región que la VM.
    • 
        
  • Redundancia del almacén: LRS, ZRS o GRS (con restauración entre regiones opcional). Se elige antes del primer backup.
    • 
      

      
Política y restauración (no está en el PDF)
    
        
  • Política: frecuencia (diaria, o cada pocas horas con la política mejorada) y retención diaria, semanal, mensual y anual.
    • 
        
  • Restaurar: crear una VM nueva, reemplazar o restaurar discos, o recuperar archivos sueltos.
    • 
        
  • Eliminación temporal: los datos de backup borrados se guardan 14 días más.
    • 
      

      
Backup vs Site Recovery (no está en el PDF)
    
        
  • Backup: copias para volver atrás en el tiempo (borrados, ransomware, auditoría).
    • 
        
  • Site Recovery (ASR): replica la VM a otra región y hace failover si cae la región: recuperación ante desastres.
    • 
        
  • RPO: cuántos datos puedes perder (tiempo desde el último punto). RTO: cuánto tardas en volver a funcionar.
    •
