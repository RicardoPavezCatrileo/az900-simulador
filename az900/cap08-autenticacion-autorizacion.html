Conceptos clave del capítulo

Microsoft Entra ID

  • Identidad y acceso en la nube (antes Azure Active Directory). No es el AD tradicional.
  • Usuarios y grupos, SSO, MFA, integración de apps, plataforma de identidad para desarrolladores, Entra ID Protection.
  • También: B2B y B2C, acceso condicional, gestión de privilegios.
  • Cada cuenta de Azure trae una instancia: el tenant de tu organización.

Confianza cero

  • Estrategia, no producto: "no confiar nunca, comprobar siempre".
  • Comprobación explícita: autenticar y autorizar siempre.
  • Privilegios mínimos: solo el acceso necesario.
  • Asumir brechas: minimizar el radio de impacto.
  • Decide por identidad y credenciales, no por la ubicación.

MFA y sin contraseña

  • Factores: algo que sabes (contraseña, PIN), algo que tienes (teléfono, llave), algo que eres (huella, rostro).
  • Sin contraseña: Windows Hello, Microsoft Authenticator, claves FIDO2.
  • Solo contraseña = baja seguridad. Contraseña + MFA = alta pero incómoda. Sin contraseña = alta y cómoda.

Usuarios externos (B2B)

  • Invitas al externo como invitado: usa su propia cuenta (Microsoft, Google, Facebook u otro proveedor).
  • Pasos: configurar el proveedor de identidad (si no es Microsoft) → invitar → asignar permisos con mínimo privilegio → opcional: apps y acceso condicional entre inquilinos.

Entra Domain Services

  • Dominio administrado (antes Azure AD DS): dos controladores de dominio por detrás, sin gestionar el SO.
  • Soporta Kerberos y NTLM para apps heredadas.
  • Sincronización unidireccional desde Entra ID; dominio independiente del AD local.
  • Usos: migrar apps que dependen de AD DS, desarrollo y pruebas.
