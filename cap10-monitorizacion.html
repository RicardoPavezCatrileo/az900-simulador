Gobernanza y monitorización

La gobernanza decide quién puede hacer qué (RBAC), cómo deben ser los recursos (Azure Policy) y qué no se puede tocar (locks). La monitorización te dice qué está pasando. Pruébalos aquí.

Crear una VM nueva

Los recursos que ya existían no se borran: Azure Policy los marca como no conformes. "Deny" frena la creación o el cambio de recursos que no cumplen; "Audit" los deja crear y los reporta.

Conceptos clave del capítulo

Policy vs RBAC vs locks

  • RBAC: quién puede hacer qué, y dónde. Roles: Lector, Colaborador, Propietario…
  • Azure Policy: cómo deben ser los recursos (regiones, etiquetas, tamaños) y cumplimiento a escala.
  • Locks: evitan borrar (Delete) o modificar (Read-only), incluso a quien tiene permisos.

Asignación de roles

  • Entidad de seguridad: usuario, grupo, entidad de servicio o identidad administrada.
  • Definición de rol: colección de permisos (leer, escribir, eliminar…).
  • Ámbito: grupo de administración, suscripción, grupo de recursos o recurso. Se hereda hacia abajo.

Azure Blueprints (retirado)

  • El curso lo explica como el "plan maestro de la ciudad": combinaba plantillas ARM, políticas y roles, con versionado.
  • ARM construye "edificios" individuales.
  • Microsoft lo retiró en julio de 2026: no le dediques tiempo para el examen.

Cloud Adoption Framework

  • Guía probada de Microsoft con prácticas, documentación y herramientas para adoptar la nube.
  • Estrategia → Planeamiento → Listo → Migración.
  • A lo largo de todo: Seguridad, Administración y Gobernanza.

Azure Monitor y familia

  • Azure Monitor: métricas y registros de Azure y de local; análisis, alertas, paneles y automatización.
  • Log Analytics: almacena y consulta registros con KQL.
  • Application Insights: rendimiento y uso de apps web.
  • Alertas: regla + grupo de acción (email, SMS, Logic Apps, Functions).
  • Service Health: incidentes y mantenimiento de Azure; gratis.
  • Azure Arc: gestión y políticas de Azure para recursos locales y de otras nubes.
