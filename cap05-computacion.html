Conceptos clave del capítulo

Escalabilidad, elasticidad y agilidad

  • Vertical (hacia arriba/abajo): una VM más grande, desde 0,5 GB de RAM y 1 vCPU hasta 11,4 TB y 416 vCPU. Tiene límites.
  • Horizontal (hacia fuera/dentro): más VMs con Scale Sets + Load Balancer. Se suele preferir.
  • Elasticidad: autoescalado según la carga.
  • Agilidad: recursos nuevos a un clic, en minutos y no semanas.
  • Alta disponibilidad: la app en al menos 2 zonas, para sobrevivir a la pérdida de un centro de datos.

VM Scale Sets

  • Grupo de VMs idénticas, copiadas de una VM base, gestionadas como una unidad.
  • Escalado manual o automático; hasta 100 VMs (configurable a 1000).
  • Opcional: Load Balancer y reparto en varias zonas.
  • Sin costo extra: pagas las VMs, el almacenamiento y la red.

Contenedores

  • Docker: empaqueta la app para que corra igual en cualquier lugar; más ligero que una VM.
  • Docker Hub: repositorio público de imágenes. Azure Container Registry (ACR): privado.
  • ACI: ejecuta contenedores bajo demanda. AKS: los orquesta con Kubernetes (código abierto).

Arquitectura web de 3 niveles

  • Load Balancer reparte el tráfico.
  • VMs en varias zonas (Scale Set multi-AZ) ejecutan la app.
  • Azure Cache for Redis guarda sesión y caché; Base de datos SQL guarda los datos.
  • App Service empaqueta este patrón para que el desarrollador solo ponga el código.

Analogía del hotel

  • Pago por uso: llegas sin reserva y pagas tarifa completa.
  • Plan de ahorro: paquete vacacional; cualquier habitación.
  • Reservada: reserva anticipada de una estadía larga.
  • Spot: subasta; te pueden desalojar.
  • Host dedicado: un piso o edificio entero para ti.
  • Aislada: suite privada separada del resto.
  • Reserva de capacidad: pagas para que la habitación esté libre cuando llegues.
